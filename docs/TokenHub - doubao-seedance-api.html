Doubao Seedance 视频生成 API 文档

火山方舟（Ark）Seedance 系列

概述

网关支持火山方舟（Ark）Seedance 系列视频生成模型（doubao-seedance-2-0-260128、doubao-seedance-2-0-fast-260128、doubao-seedance-2-0-mini-260615、doubao-seedance-2-5-260628），采用 创建任务 → 轮询结果 的异步调用模式。

接入协议：网关地址的协议前缀随部署环境不同：测试环境为 http://，生产环境为 https://。本文档所有示例统一以测试环境 http://<gateway-host> 为基准，仅作演示；接入生产环境时请将前缀替换为 https://，<gateway-host> 替换为实际网关域名。

模型列表

模型名称 类型 说明
doubao-seedance-2-0-260128 标准版 豆包 Seedance 2.0 标准视频生成模型
doubao-seedance-2-0-fast-260128 快速版 快速视频生成，推理速度更快
doubao-seedance-2-0-mini-260615 Mini 版 轻量化模型，适合简单任务
doubao-seedance-2-5-260628 2.5版 豆包 Seedance 2.5 视频生成模型

调用流程

视频生成采用异步任务模式，分两步完成：

  1. 提交任务：调用 POST /v1/videos/generations（或原生路径 POST /api/v3/contents/generations/tasks），返回任务 ID（output.task_id）
  2. 轮询结果：调用 GET /v1/videos/generations/task/{taskId}（或原生路径 GET /api/v3/contents/generations/tasks/{taskId}）查询状态
双路径兼容：网关同时支持 OpenAI 兼容路径 /v1/videos/generations 与火山方舟原生路径 /api/v3/contents/generations/tasks（查询同理），两条路径行为完全一致，可任选其一。

状态流转：

queued → running → succeeded / failed

queued 或 running 超过过期时间 → expired

一、提交视频生成任务

1.1 请求地址

HTTPPOST /v1/videos/generations
HTTP（火山原生路径）POST /api/v3/contents/generations/tasks

两条路径行为完全一致，可任选其一。

1.2 请求头

Header 必填 说明
Content-Type 是 固定为 application/json
Authorization 是 格式：Bearer <your-api-key>
Seedance 系列无需设置 X-DashScope-Async 请求头。

三、素材管理接口（通用约定）

视频生成常需引用已上传的参考图片/视频/音频。网关提供素材库能力，对素材组（AssetGroup）和素材（Asset）做 CRUD，统一中转到火山素材库上游。

3.1 统一入口

HTTPPOST /v1/api/asset?Action=<Action>&Version=2024-01-01
  • Action 决定具体接口，Version 固定 2024-01-01
  • 全部 POST 方法，Content-Type: application/json
  • 鉴权：Authorization: Bearer <your-api-key>（必填）
  • 请求体字段名 PascalCase（如 Name、GroupId、Filter.GroupIds）

ListAssetGroups列出素材组四.2

六、视觉校验（VisualValidate）

视觉校验用于真人活体认证。调用 CreateVisualValidateSession 创建认证会话，上游返回 BytedToken；用户在 H5 页面完成认证后，网关定时轮询 GetVisualValidateResult，认证成功后回填 GroupId 并将组转为 active。认证完成的真人组（GroupType=LivenessFace）可在 ListAssetGroups 中通过 Filter.GroupType=LivenessFace 查询。

与 AIGC 组的区别：真人组（LivenessFace）不能通过 CreateAssetGroup 创建，只能通过 CreateVisualValidateSession 创建；其生命周期由认证状态驱动（pending -> active / failed），而非 Create 即 active。

七、视频生成中的 asset:// 引用

视频生成接口 POST /v1/videos/generations（或原生路径 POST /api/v3/contents/generations/tasks）的 content 数组里，可用 asset://<Id> 引用已创建的素材替代公网 URL。网关在转发上游前自动校验所有 asset:// 引用是否归属当前 Authorization key，不属于则 fail-closed 返回 403。

7.1 三种引用写法

JSON// 图片引用（role: reference_image / first_frame / last_frame）
{"type":"image_url","role":"reference_image","image_url":{"url":"asset://182533555060998168"}}

// 视频引用（role: reference_video）
{"type":"video_url","role":"reference_video","video_url":{"url":"asset://<Id>"}}

// 音频引用（role: reference_audio）
{"type":"audio_url","role":"reference_audio","audio_url":{"url":"asset://<Id>"}}

7.2 归属校验行为

场景结果
引用自己 key 下的 Active 素材200 放行，正常生成 task_id
引用他人 key 下的素材403 asset not owned by key: [...]
一次请求引用了多个不同 provider 的素材403 assets from multiple providers in one request
content 里无 asset:// 引用（纯文生视频/公网 URL）200 不校验，直接放行
归属校验服务不可用/超时403 fail-closed

7.3 端到端示例（建组 → 建素材 → 轮询 Active → 视频生成）

BashGATEWAY="http://<gateway-host>"
API_KEY="<your-api-key>"

# 1. 创建素材组
GROUP_ID=$(curl -s -X POST "${GATEWAY}/v1/api/asset?Action=CreateAssetGroup&Version=2024-01-01" \
  -H "Content-Type: application/json" -H "Authorization: Bearer ${API_KEY}" \
  -d '{"Name":"视频素材组","GroupType":"AIGC"}' | jq -r '.Id')
echo "组 ID: ${GROUP_ID}"

# 2. 创建素材（图片）
ASSET_ID=$(curl -s -X POST "${GATEWAY}/v1/api/asset?Action=CreateAsset&Version=2024-01-01" \
  -H "Content-Type: application/json" -H "Authorization: Bearer ${API_KEY}" \
  -d "{\"GroupId\":\"${GROUP_ID}\",\"URL\":\"https://example.com/cat.jpg\",\"AssetType\":\"Image\",\"Name\":\"猫咪\"}" \
  | jq -r '.Id')
echo "素材 ID: ${ASSET_ID}"

# 3. 轮询素材就绪（Status=Active）
while true; do
  STATUS=$(curl -s -X POST "${GATEWAY}/v1/api/asset?Action=GetAsset&Version=2024-01-01" \
    -H "Content-Type: application/json" -H "Authorization: Bearer ${API_KEY}" \
    -d "{\"Id\":\"${ASSET_ID}\"}" | jq -r '.Status')
  echo "素材状态: ${STATUS}"
  [ "${STATUS}" = "Active" ] && break
  sleep 5
done

# 4. 提交视频生成任务，用 asset:// 引用素材
TASK_ID=$(curl -s -X POST "${GATEWAY}/v1/videos/generations" \
  -H "Content-Type: application/json" -H "Authorization: Bearer ${API_KEY}" \
  -d "{\"model\":\"doubao-seedance-2-0-260128\",\"content\":[{\"type\":\"text\",\"text\":\"图片1 一只猫在花园里奔跑\"},{\"type\":\"image_url\",\"role\":\"reference_image\",\"image_url\":{\"url\":\"asset://${ASSET_ID}\"}}],\"duration\":5}" \
  | jq -r '.output.task_id')
echo "任务 ID: ${TASK_ID}"

# 5. 轮询视频生成结果
while true; do
  RESULT=$(curl -s "${GATEWAY}/v1/videos/generations/task/${TASK_ID}" \
    -H "Authorization: Bearer ${API_KEY}")
  STATUS=$(echo "${RESULT}" | jq -r '.status')
  echo "任务状态: ${STATUS}"
  if [ "${STATUS}" = "succeeded" ]; then
    echo "视频 URL: $(echo "${RESULT}" | jq -r '.content.video_url')"
    break
  elif [ "${STATUS}" = "failed" ]; then
    echo "失败: $(echo "${RESULT}" | jq -r '.error.message')"
    break
  fi
  sleep 10
done

Pythonimport requests
import time

HEADERS = {
    "Content-Type": "application/json",
    "Authorization": f"Bearer {API_KEY}"

# 1. 提交 Seedance 视频生成任务
create_url = f"{GATEWAY}/v1/videos/generations"
payload = {

        {
            "type": "text",

        {
            "type": "image_url",
            "image_url": {"url": "https://example.com/sunset.jpg"},
            "role": "reference_image"
        }
    ],
    "duration": 5,
    "ratio": "16:9"
}

response = requests.post(create_url, json=payload, headers=HEADERS)
result = response.json()

if response.status_code != 200:

query_url = f"{GATEWAY}/v1/videos/generations/task/{task_id}"
while True:
    time.sleep(10)
    resp = requests.get(query_url, headers=HEADERS)
    result = resp.json()

H = {"Content-Type": "application/json", "Authorization": f"Bearer {API_KEY}"}

def asset(action, body):
    r = requests.post(f"{GATEWAY}/v1/api/asset?Action={action}&Version=2024-01-01", json=body, headers=H)
    return r.json()

# 1. 创建素材组
group = asset("CreateAssetGroup", {"Name": "视频素材组", "GroupType": "AIGC"})
group_id = group["Id"]

})
asset_id = asset_resp["Id"]

# 3. 轮询素材就绪
while True:

    if s == "Active":

十、注意事项

有效期限制：task_id 及视频下载 URL 有效期为 24 小时，请及时下载。
轮询间隔：建议 5–15 秒轮询一次，避免过于频繁。
无需 X-DashScope-Async 头：Seedance 系列使用 task-based 端点，不需要此请求头。
素材引用规则：在 type: "text" 中，按 content 数组顺序从 1 开始编号，使用 图片N / 视频N / 音频N 引用对应素材（如 图片1、视频1、音频1，不带方括号，中文写法，Seedance 仅识别此格式）。
素材 URL 有效期：GetAsset / ListAssets 返回的 URL 由上游签发，约 12 小时失效，需及时使用。
素材就绪才可引用：仅 Status=Active 的素材可用于视频 asset:// 引用；创建后通常需轮询 5–30 秒等待 Processing → Active。
跨 key 引用禁止：asset:// 引用他人 key 下的素材会被 fail-closed 拦截返回 403。
私有隔离：素材组/素材的查询、更新、删除均带 key 归属过滤，越权访问与资源不存在统一返回 404。
